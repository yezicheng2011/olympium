====================================================================
Olympium Universal OS (ISO) — 已知安全风险与无法单靠代码根除的限制
(KNOWN_VULNERABILITIES.txt)
====================================================================

一、已在本次审计中直接修复的代码漏洞
--------------------------------------------------------------------
1. [已修复] 供应链未校验下载 (CWE-494):
   image/stage-mobile-slim.sh 原本直接 curl 下载 microG APK 无哈希校验；
   已改为强制要求 OLYMPIUM_MICROG_GMS_SHA256 校验（不匹配直接拒绝并删除），
   且强制 HTTPS + TLS 1.2+。
2. [已修复] .desktop / library.tsv 换行注入 (CWE-74):
   vbnet/Olympium/InstallApp.vb 已对所有写入 .desktop 与 TSV 的应用名、
   ID、图标路径过滤控制字符与换行符，防止恶意包名注入额外 Exec= 指令。
3. [已修复] 跨平台剪切板/URI 注入 (CWE-78 / CWE-20):
   vbnet/Olympium/InteropHub.vb 已对 Android ADB 剪切板参数采用严格
   POSIX 单引号转义并限制 64 KiB + 剥离 NUL，仅放行 http/https/mailto URI，
   并对共享文件名做字符白名单过滤。

二、受架构或上游限制、无法单靠本项目代码根除的已知风险
--------------------------------------------------------------------
1. [高] 双击即装即运行 / binfmt_misc 自动执行攻击面 (Architectural)
   - 风险：开启 binfmt_misc 自动执行 MZ/PE 与跨架构 ELF 后，用户在终端或
     文件管理器双击来源不明的 .exe/.deb/.rpm/ELF 会直接进入 Wine 或 QEMU
     用户态执行，Wine 默认共享当前用户主目录与剪贴板，恶意程序可读写用户文件。
   - 无法根除原因：属于“双击即原生运行”产品交互与 Wine/Linux 用户态权限模型
     的固有权衡。
   - 缓解建议：仅安装可信来源软件；必要时对高风险 Windows 程序使用独立
     OLYMPIUM_WINE_PREFIX 并在设置中关闭自动剪贴板共享。

2. [中] 非特权 User Namespace 放宽 (kernel.apparmor_restrict_unprivileged_userns=0)
   - 风险：image/build-iso.sh 为兼容 Firefox 沙箱关闭了 Ubuntu 24.04 的
     AppArmor userns 限制，这会扩大 Linux 内核用户命名空间相关提权漏洞的本地
     利用面。
   - 无法根除原因：Live ISO 下 Firefox 内容沙箱依赖非特权 userns。
   - 缓解建议：及时通过 Ubuntu 安全仓库更新发行版内核与浏览器。

3. [中] 上游组件固有漏洞 (Linux Kernel / Wine / QEMU / Darling / Firefox / .NET 8)
   - 风险：ISO 打包了静态快照版本的发行版内核、QEMU-user-static、Wine、
     Darling 与 Firefox；上游后续披露的 CVE 无法在旧 ISO 镜像中自动消失。
   - 无法根除原因：取决于上游安全更新，且未修改内核。
   - 缓解建议：装机后定期运行 apt upgrade 或重新使用 build-iso.sh 构建新镜像。

4. [中] microG 签名伪装 (Signature Spoofing) 风险
   - 风险：Android 端启用 microG 所需的 Signature Spoofing 权限若被恶意 APK
     滥用，可能冒充系统或 GMS 签名。
   - 无法根除原因：开源 microG 替代闭源 GMS 的必要机制。
   - 缓解建议：仅授予受信任的官方 microG GmsCore 签名伪装权限，切勿全局放开。

5. [中] 跨生态共享剪贴板信息泄露 (Cross-Boundary Clipboard Leakage)
   - 风险：双向剪贴板同步开启时，宿主机复制的密码/令牌会同步至 Wine、
     Android 或鸿蒙侧，可能被侧方应用读取。
   - 缓解建议：复制敏感凭据前可在设置页临时关闭“Shared Clipboard”开关。

6. [低] Live ISO 明文写入内存 overlay / 无默认全盘加密 (LUKS)
   - 风险：Live 模式与 install-to-disk 默认未启用全盘 LUKS 加密。
   - 缓解建议：生产环境建议在装盘后配置 LUKS 加密分区或加密主目录。
