Manual

Install the published Mac package, start Olympium, and see which guest runtimes exist. This page does not add a host or a guest that the software cannot run.

Install

macOS

The published 0.1.0 installer is a component package. It puts Linkspan.app in /Applications. That file name and the download URL stay as they are. The app inside is ad-hoc signed. The .pkg itself is unsigned, and it is not notarized. macOS can warn before it opens. That warning is real. Nothing on this site removes it. A later build can be named Olympium. It is not this download.

Download Linkspan-0.1.0.pkg. The same file is on GitHub.

SHA-256: ba96038bd318d7ec1a47fb3cbf93dd2e7d0bb92222fcb9f670f3dc2be0130de0

There is no iOS app. This package does not contain a guest image.

Linux, Windows, Android, and OpenHarmony

There is no published .deb, .rpm, AppImage, Windows installer, APK, or HAP on the download page. Build those clients from the source repository when you have the SDK for that host. The OpenHarmony SDK is not in the repository. Without it, a HAP is not produced.

Start

On a Mac, open /Applications/Linkspan.app from the 0.1.0 package. The command linkspan remains available as an alias where a newer build also installs olympium. If macOS says the app cannot be opened because the developer cannot be verified, that follows from the ad-hoc signature and the lack of notarization. The package does not claim otherwise.

On Linux, after you build the command:

olympium doctor
olympium-linux

The desktop window needs GTK 4 and libadwaita from the system. They are not copied into the Mac package.

Use

Add a program you already have, then run it. Olympium does not download applications.

olympium add --file ./program.deb
olympium list
olympium run --file ./program.deb

A legal refusal exits with status 2. A missing engine exits with status 3. olympium limits prints the rules, including the refusal of macOS and iOS software on non-Apple hardware.

Guest images are not inside the app. olympium runtime reads the client IP and chooses GitHub, or a China mirror when the country is CN. olympium fetch downloads a published archive and checks SHA-256. A mismatch is discarded.

Download progress

olympium fetch --guest linux prints downloaded and a byte count while the archive is coming in, then the final count when the transfer finishes. The file is kept only after the SHA-256 matches. olympium guest --guest linux boots that extracted image and waits until the guest prints olympium-linux-guest-ok. The same progress line is used for Wine. Android and OpenHarmony stop with “not published” and do not invent a file. Wine in that archive is a Linux x86_64 program, so a Mac cannot run it directly.

Uninstall

On a Mac, delete /Applications/Linkspan.app to remove the 0.1.0 install. The package receipt does not delete that app for you. pkgutil --forget app.linkspan.macos only drops the 0.1.0 receipt. A later Olympium build would use its own app name and receipt, and it is not published here.

A source build on Linux is removed by deleting the binaries you installed. There is no published Linux package on this download page.

Signing

The 0.1.0 app is ad-hoc signed. The installer package is unsigned and not notarized. Open it only if you accept that macOS warning. Guest runtimes are separate downloads. They are not Apple-signed, and this site does not claim they are.

One file, two formats

This is an experiment. It is not the Mac download, and it is not offered from the button above. Changing the extension does not change the bytes. It also does not turn the file into every installer, and it does not silence a platform warning.

One tested file is a Debian package with a zip archive after it. The copies named .deb and .zip were the same bytes. dpkg-deb read the package. dpkg -i installed a small probe script and dpkg -r removed it. The recorded install printed linkspan-polyglot-probe-ok. The source script now prints olympium-polyglot-probe-ok. Python’s zip reader extracted the zip members from those same bytes.

The same construction was repeated with the 0.1.1 Linux command before this rename. The file is 2487905 bytes, SHA-256 e0336a1fbf6c7ae2967144989fc8a68f7a7f818094f756ed68fbfdc8d77161de. After dpkg -i, /usr/lib/linkspan-polyglot/linkspan --version printed linkspan 0.1.1. The zip member was the same program bytes. Zip extraction does not keep the executable bit; the Debian package does. The package was then removed. It is not signed. It is not published next to the 0.1.0 Mac package. That file was not rebuilt after the command was renamed, so this checksum still belongs to the linkspan binary.

Info-ZIP’s unzip prints extra bytes at beginning or within zipfile and exits 1, after extracting the member. file reports only a Debian package. GNU ar rejects the file. rpm and msiinfo reject it.

A Debian package, an RPM, an MSI, a Windows exe, and a macOS pkg each need a different signature at the first byte. One file cannot start with all of them. An Android APK or OpenHarmony HAP was not built into this file. Their signing covers offsets from the start, so a prefix or a suffix would break that signature. A disk image wants its trailer at the end of the file, and that combination was not tested.

Rebuild the probe with scripts/test-polyglot-deb-zip.sh from the source tree. The engineering notes are in docs/polyglot.md in that tree.
